Rulith Inference 0.6.8 fixes the garbled answers that EXL3 3.05 bpw could give in 0.6.7 with MTP and sampling on, the app's defaults. Speeds are those of 0.6.7.

**Fix**
- With MTP on and a temperature above 0, EXL3 3.05 could answer in garbled text from the first sentence on: fragments of other languages repeating ("えると", "sunrise"). The cause was in how the engine waits for the GPU. Since 0.4.9 it watches a marker that the GPU writes after its work, which is faster than the runtime's own wait. That marker could arrive before an MTP verification's results (2-3 MB of token scores) had finished copying to the CPU, and part of them was then read as the previous step had left them. 0.6.7 made 3.05's verification steps fast enough to hit this often.
- The GPU now copies those results itself, in the same queue as the marker, so the marker follows the copy. Other copies to host memory fall back to the runtime's wait. The affected copy path is shared by models; the reported garbling was reproduced with EXL3 3.05, MTP and sampling.
- MTP-off and greedy regression probes showed no change in the tested outputs.

**Speed** (one machine, EXL3 files, 256-token answers, tokens per second; 0.6.7 as in its release notes, 0.6.8 two rounds):

| | 0.6.7 | 0.6.8 | Draft acceptance, both versions |
|---|---|---|---|
| 4.05, MTP off | 34.5 | 34.4 | n/a |
| 4.05, MTP on, prose | 46.7 | 46.7 | 45.1% |
| 4.05, MTP on, explanation | 59.9 | 59.8 | 69.1% |
| 4.05, MTP on, code | 66.4 | 66.4 | 80.7% |
| 3.05, MTP off | 38.4 | 38.5 | n/a |
| 3.05, MTP on, explanation | 60.9 | 61.3 | 61.3% |
| 3.05, MTP on, code | 77.5 | 77.7 | 84.7% |

Draft acceptance is accepted draft tokens divided by proposed draft tokens for that workload. Prompt reading is unchanged.

**Switches**
- `STRIX_POLL_D2H_KERNEL=0` (an environment variable of the server) copies the results the old way and then uses the runtime's wait; `STRIX_POLL_SYNC=0` uses the runtime's wait throughout.

**Validation**
- Recorded sampled answers with MTP for EXL3 3.05 and 4.05, three seeds each, are byte-identical between the polling wait and the runtime's own wait. This comparison covers the reported failure settings.

**For source builds**
- The engine source is `rulith-dev/llama.cpp`, branch `rulith`, commit `ee07b49d083716fe316a5f66c35c8a2ccc8184eb`. The bundled engine was compiled before that commit was recorded, so its build string still shows the preceding `f96350fb9` revision. The recipe reproduces all 181 changed files of the fixed commit, and the packaged engine files match the validated build.
