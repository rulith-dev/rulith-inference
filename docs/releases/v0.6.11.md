Rulith Inference 0.6.11 adds Qwen3.6-35B-A3B ([#24](https://github.com/rulith-dev/rulith-inference/issues/24)), reads several equal-length prompts at full speed again ([#25](https://github.com/rulith-dev/rulith-inference/issues/25)) and no longer fails a conversation whose tool output quotes the server's media marker ([#26](https://github.com/rulith-dev/rulith-inference/issues/26)).

**Qwen3.6-35B-A3B**
- The Downloads page offers Unsloth's UD-Q4_K_XL file with its MTP layer (22.9 GB) and the image projection (0.9 GB). On the 64 GB setting it loads whole on the GPU and leaves room for long conversations; on smaller settings some expert layers move to system memory.
- The app recognises the family by name, turns MTP on when the file carries its MTP layer (drafts come from that layer, no extra file) and image input when the projection sits beside the model. Files without the MTP layer, such as LM Studio's, load with MTP off.
- One conversation, 64 GB setting: 56-58 tok/s with MTP off and 73-76 tok/s with MTP on (draft acceptance about 60%), 68 tok/s with MTP on behind a 32K-token prompt. Prompt reading: about 1,800 t/s at 512 tokens, 2,600 at 4K and 1,500 at 32K. Eight conversations together: 183 tok/s summed with MTP off, 198 with it on.
- Images, tool calls (also while thinking and streamed) and the thinking switch work as with the other families; low/medium/high thinking all mean "on" for this model.
- It runs on the kernels its shapes meet; none of the Qwen3.8-Flash-Next work is specific to it yet.

**Equal-length prompts in one batch (#25)**
- When every conversation in a batch had the same number of prompt tokens, the batch was split differently from the uneven case: the two conversations went into one group that the fast delta-net kernels do not take. Two 2048-token prompts sent together read at about 800 t/s, against about 1,230 t/s for 2047 + 2049 tokens.
- Equal counts of 16 tokens or more now keep one group per conversation: about 1,180-1,240 t/s for the equal case. One conversation is unchanged.
- Thanks to @depechetoi for the precise measurements.

**The media marker in conversation text (#26)**
- `/props` reports the marker the server uses to place an image in a prompt. An agent that quoted it in a tool result left a marker without an image in the history, and every later request of that conversation failed with HTTP 400 "Failed to tokenize prompt".
- Copies of the marker in message text are now replaced with a neutral `<__media__>` before images get their markers, so text can no longer be taken for an image slot.
- Thanks to @depechetoi for the report.

**Unsloth's UD files decode a little faster**
- The expert and shared down projections of one-token steps (K 352-1024) run four rows per work group, multi-token expert products of the MTP verification take four rows at once, and the router's small products a narrower kernel: about 3% less time per decoded token, 2% per verification step. Every value comes out bit for bit as before.

**For people who build the engine themselves**
- The engine source is `rulith-dev/llama.cpp`, branch `rulith`, commit `0364508f0`. The patch set replays byte for byte; `patches/MANIFEST.md` records the changes and their measurements.
