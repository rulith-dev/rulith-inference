Rulith Inference 0.6.9 decodes several conversations at once faster and tells the model today's date.

**Several conversations at once**
- When eight conversations answer together, each step computes one token of each: products of eight rows. The EXL3 files' dense projections of five to eight rows went to a kernel that read the weights at 100-163 GB/s. They now take the streaming ring that one to four rows have used since 0.6.7, and each row comes out bit for bit as the one-row path computes it.
- Sampling those eight rows built the full list of 248K candidates for each row, on a thread of its own. The exact fast top-k sampler of 0.6.3 now takes them one after the other, and its scan skips eight scores at a time where none can be a candidate. The CPU time between two such steps went from 1.6 to 0.5 ms. Every sampled token is the one the full sampler chain draws.
- EXL3 4.05, eight conversations, MTP off: 84.8 -> 91.2 tok/s summed (+7.5%). With MTP on, the app's default, the sum moves within its run-to-run spread: at eight conversations a verification step carries 16 to 32 tokens, which this change does not touch. One conversation is unchanged.

**Today's date**
- The model has no clock. Since 0.2.5 the app no longer put the date into the system prompt, because a date that changes every day invalidated every conversation's prompt cache, so a model asked for the date guessed one from its training data. The app now writes the date in front of a conversation's first message, and in front of the first message of each later day. The date comes from that message's own time, so earlier messages never change and their cache stays valid.

**Documentation**
- The README and the getting-started guide are rewritten around the installer, the downloads inside the app and the recommended EXL3 file, with current measurements. The engine's change-by-change history moved to `docs/engine.md`.

**Speed** (one machine, EXL3 4.05, tokens per second, 0.6.8 and 0.6.9 interleaved):

| | 0.6.8 | 0.6.9 |
|---|---|---|
| eight conversations, MTP off (384-token answers, summed, six runs) | 84.8 | 91.2 |
| eight conversations, MTP on (six runs, from 73 to 90 each) | 81.3 | 84.9 |
| one conversation, MTP off (prose, chat, code) | 33.0 | 33.1 |
| one conversation, MTP on, explanation (draft acceptance 66%) | 58.2 | 58.5 |

Prompt reading is unchanged.

**Switches**
- `STRIX_MMH_RING2_MAX=4` (an environment variable of the server) sends products of five to eight rows to the previous kernel.

**For people who build the engine themselves**
- The engine source is `rulith-dev/llama.cpp`, branch `rulith`, commit `511901542`. The patch set replays byte for byte; `patches/MANIFEST.md` records the changes and their measurements.
